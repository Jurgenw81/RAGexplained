🧠 1. What is RAG?

Retrieval‑Augmented Generation (RAG) is a technique that gives large language models (LLMs) access to external, up‑to‑date, or private knowledge without retraining. Instead of relying only on what the model learned during training, RAG fetches relevant documents at inference time and feeds them to the model as context.

Think of it as an open‑book exam: the LLM is the student, and the retriever finds the right pages from a textbook (your knowledge base) before the student writes the answer.

⚡ 2. Why use RAG?

🕒

Up‑to‑date knowledge

LLMs have a knowledge cutoff. RAG injects fresh data from databases, APIs, or documents — no fine‑tuning needed.

🔒

Private & domain‑specific

Use internal wikis, legal contracts, or customer support tickets without exposing them to the model during training.

🎯

Reduced hallucinations

Answers are grounded in retrieved evidence. The model can cite sources and say “I don’t know” when context is missing.

💰

Cost‑effective

No expensive fine‑tuning or retraining cycles. Update the retrieval index, not the model weights.

⚙️ 3. Two phases: indexing & inference

RAG systems have two distinct pipelines that work together.

📦 A. Indexing (offline / pre‑processing)

  • Collect documents — PDFs, web pages, databases, APIs, Notion pages, etc.
  • Chunk — split text into manageable pieces (e.g., 200–500 tokens with overlap).
  • Embed — convert each chunk into a vector using an embedding model (e.g., text‑embedding‑3, BGE, E5).
  • Store — save vectors + metadata in a vector database (Pinecone, Weaviate, Qdrant, FAISS, Chroma).

💬 B. Inference (online / query time)

  • Receive query — user asks a question.
  • Embed query — same embedding model as indexing.
  • Retrieve — find top‑k most similar chunks (cosine similarity, dot product, etc.).
  • Augment prompt — insert retrieved chunks into the LLM’s context window.
  • Generate — LLM produces an answer grounded in the retrieved context.

🔬 4. Inside the pipeline

📄 Chunking strategies

Fixed‑size

Split by token/character count with overlap. Simple but may cut sentences.

Recursive

Split by paragraphs → sentences → words. Preserves semantic boundaries better.

Semantic

Use embeddings to detect topic shifts. Higher quality, more compute.

🧮 Embedding models

They map text to high‑dimensional vectors where similar meanings are close together. Popular choices: OpenAI text‑embedding‑3‑small BGE‑large E5‑mistral Cohere Embed v3.

🗂️ Vector databases

Specialized stores for efficient similarity search. Options: Pinecone (managed), Qdrant (open‑source), FAISS (library), Chroma (lightweight), Weaviate (hybrid search), pgvector (Postgres extension).

# simple RAG inference flow (pseudo‑code)
query = "How does RAG reduce hallucinations?"
query_vec = embed(query)
chunks = vector_db.search(query_vec, top_k=5)
context = "\n\n".join(chunks)
prompt = f"""Answer based only on this context:
{context}
Question: {query}"""
answer = llm.generate(prompt)

⚠️ 6. Challenges & best practices

Retrieval quality

Garbage in → garbage out. Use good chunking, hybrid search, and reranking to surface relevant context.

Context length

Too many chunks → lost in the middle. Keep top‑k small (3–8) and use reranking.

Freshness

Re‑index regularly or use change data capture (CDC) to keep the vector store updated.

Evaluation

Measure retrieval (recall@k, MRR) and generation (faithfulness, answer relevance). Use RAGAS or TruLens.

🚀 7. RAG from start to end — summary

  1. Ingest — load documents from any source.
  2. Chunk — split into meaningful pieces.
  3. Embed — vectorise each chunk.
  4. Store — persist vectors + metadata in a vector DB.
  5. Query — user asks a question.
  6. Embed query — same model as indexing.
  7. Retrieve — find top‑k nearest chunks.
  8. Augment — build a prompt with context.
  9. Generate — LLM produces the final answer.
  10. Iterate — evaluate, refine, and improve.

💡 The key takeaway: RAG connects a retriever (which knows where to find information) with a generator (which knows how to express it). This combination makes LLMs more accurate, transparent, and adaptable to any domain — without touching the model weights.
